Verified end to end against the current Okta admin console. New to this? Read [Single Sign On](/site-access/single-sign-on) first for the why.

## 1. Create the application

**Applications → Applications → Create App Integration**

- Sign-in method: **OIDC - OpenID Connect**
- Application type: **Web Application**
- Grant type: **Authorization Code**
- Sign-in redirect URI: your site's callback address
- Copy the **Client ID** and **Client secret** from the **General** tab

<Warning>
The redirect URI must match exactly. Check it first if sign in fails.
</Warning>

## 2. Create the service account

**Directory → People → Add Person**

| Field | Value |
| --- | --- |
| User type | User |
| First / Last name | Superflow / Agent |
| Username | an email address you control |
| Primary email | the same address |
| Activation | Activate now |
| **I will set password** | **Tick this** |

**I will set password** is required. Without it, Okta emails an activation link the agent cannot receive.

After ticking it: set a password and **untick "User must change password on first sign-in"**.

<Tip>
Okta rejects passwords containing parts of the username or name.
</Tip>

## 3. Create a group

**Directory → Groups → Add group** → name it `superflow-agents` → add the service account.

The group exists as a target for the policy rules below, not for application access.

<Note>
**You may not need to assign the app to anyone.** If **Assignments** says _"This app is implicitly assigned to users"_ (Federation Broker Mode, the default for new OIDC apps), access is controlled entirely by sign on policy.
</Note>

## 4. The three policies

All three target `superflow-agents`. All three are required.

### a. Application sign on policy

**Security → Authentication Policies** → open the policy your app uses.

Add a rule:

- IF **User's group membership includes** → `superflow-agents`
- THEN **Access is Allowed**, **User must authenticate with** a single factor option such as *Password / IdP*

Avoid options containing *"2 factor types"* or *"+ Another factor"*.

Okta warns that single factor rules are weak. Click **Save anyway**. The warning is expected here: this rule applies only to one non-human account.

<Warning>
**Check which apps share this policy.** New OIDC apps often attach to a shared default policy, so your exemption follows the service account to every app using it. Usually fine (one non-admin account). If the **Okta Admin Console** shares it, clone the policy and attach only your app.
</Warning>

### b. Global session policy

**Security → Global Session Policy** → add a rule for `superflow-agents` with **Multifactor authentication: Not required**, placed above the default.

Separate from the app policy. One governs opening the app; this one governs establishing an Okta session.

### c. Authenticator enrollment

**Security → Authenticators → Enrollment** → add a policy for `superflow-agents`:

- **Password**: required
- **Authenticator apps**: Optional or Disabled
- **Email**: Disabled (Optional is often rejected when email is recovery-only)

Place it above the default.

## 5. Prove it before involving an agent

Open a **private browser window** and sign in to your protected page as the service account.

Success looks like: username, password, content. No code prompt. No enrollment screen. No password change.

If any extra screen appears, that is the policy still to fix.

<Note>
The Okta **admin console** will still prompt you for multi-factor. That applies to your administrator account, not the service account. Leave it alone.
</Note>

## 6. Connect it in Superflow

- Open **Superflow project settings**.
- Enable **This project is password protected**.
- In **Site Access**, enter the service account's username and password.
- Choose **Single sign on**.
- Press **Test access**.

`okta.com` is a recognised provider, so Superflow signs in directly without asking you to confirm the address.
